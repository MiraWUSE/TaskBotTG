# Развёртывание на Bot-Hosting.net

Инструкция для Python-приложения в [панели Bot-Hosting.net](https://bot-hosting.net/a/). Создайте deployment в своём аккаунте и загрузите исходники из этого репозитория. Для переноса существующих задач дополнительно перенесите согласованную резервную копию SQLite при остановленных исходной и новой копиях бота.

## Настройки приложения

| Параметр | Значение |
|---|---|
| Runtime | Python 3.12 |
| Entry File | `main.py` в корне архива |
| Зависимости | `requirements.txt`, установка при запуске |
| Рабочий каталог | `/home/container` |
| `DATABASE_PATH` | `data/bot.sqlite3` |
| Полный путь к SQLite | `/home/container/data/bot.sqlite3` |
| `BOT_TIMEZONE` | `Europe/Moscow` |
| `BOT_TOKEN` | Секретная переменная в Env; значение в документации не хранится |
| Ресурсы | Зависят от выбранного тарифа; проверьте лимиты в панели |

Корневой `main.py` вызывает `bot.main.main()`. Если задаёте Startup вручную, сохраните установку зависимостей:

```sh
python -m pip install --no-cache-dir -r requirements.txt && exec python main.py
```

На этом хостинге Dockerfile и Compose не используются. Файлы приложения и `data/` находятся в постоянном каталоге deployment и сохраняются при обычном перезапуске. Компьютер можно выключать, пока серверное приложение работает.

**Одновременно должна работать только одна копия с этим токеном.** Перед локальным запуском остановите сервер в панели и дождитесь статуса остановки. Перед возвратом на хостинг остановите локальную копию.

## Бесплатный тариф и продление

Free требует **ручного продления каждые 4 дня**. Точную дату смотрите в Billing панели; кнопка продления становится доступна за 3 дня до срока. Это действие выполняет владелец аккаунта.

Если срок пропущен, приложение останавливается сразу. На продление остаётся 3 дня, затем deployment вместе с файлами удаляется. Финальная копия доступна для восстановления ещё 30 дней. У Free нет гарантии непрерывной работы: возможны перезапуски и перемещения без предупреждения.

Условия проверены по [официальным тарифам](https://bot-hosting.net/pricing), [правилам сервиса, разделы 3.5–3.6](https://bot-hosting.net/legal) и [changelog от 14.10.2026](https://bot-hosting.net/changelog). Собственные копии SQLite храните вне хостинга.

## Управление и обновление

- **Console:** просмотр логов, Start, Stop и Restart. После запуска дождитесь `Run polling` без ошибок авторизации, `Conflict` или доступа к SQLite; затем проверьте `/tasks` в Telegram.
- **Files:** исходники, `requirements.txt`, каталог `data/` и резервные копии.
- **Env:** токен и настройки. Сохранение настроек может запустить или перезапустить приложение; проверяйте статус в Console.
- **Startup:** Python и корневой `main.py`. Не меняйте тип runtime и не запускайте переустановку при обычном обновлении: это может удалить файлы.

Порядок обновления: создайте backup → Stop и дождитесь остановки → загрузите и распакуйте исходники → проверьте Startup → Start → проверьте логи и `/tasks`. Публикация коммита в GitHub сама по себе не обновляет приложение: в этой конфигурации автоматическое развёртывание не настроено.

В архив обновления не включайте `.env`, `.venv`, локальную SQLite и её `-wal`/`-shm`. Сохраняйте существующий серверный `data/`; корневые `main.py`, `requirements.txt` и `bot/` должны остаться на своих местах. Не удаляйте deployment для обновления кода.

## Обновление до improvements v1 со старой схемы

1. Создайте копию командой ниже и скачайте её за пределы хостинга. Убедитесь, что в Files достаточно места для ещё одной полной копии SQLite и перестройки таблицы доставок.
2. Остановите бота и дождитесь завершения процесса. Не запускайте параллельную локальную копию с этим токеном.
3. Загрузите проверенные исходники нужного коммита и `requirements.txt`. Сохраните серверные Env и каталог `data/`; не загружайте локальную базу поверх серверной. Startup остаётся `main.py`, Python 3.12.
4. Запустите приложение. При первом подключении SQLite автоматически обновится с v1–v9 до v10 в одной транзакции. Перед этим создаётся дополнительная проверенная копия в `/home/container/data/backups/pre-migration-v<версия>-<время>-<id>.sqlite3`. При нехватке места, ошибке копирования или миграции запуск прекратится, схема не останется обновлённой частично. Перестройка задач в v7 сохраняет связи с доставками, интервалами и подзадачами; они проверяются до коммита. v8 добавляет журнал выполнений и восстанавливает доступную старую историю, v9 — привычки, v10 — выключенные тихие часы и состояние отложенной очереди. Скачайте и резервную копию через Files.
5. Проверьте логи, `/tasks`, `/today`, личный пояс и существующую повторяющуюся задачу. Старые задачи получат средний приоритет, категорию «Другое» и выключенные предварительные уведомления. Проверьте на новой тестовой задаче быстрое создание с подтверждением, изменение приоритета/категории и предупреждение за 5 минут при сроке более чем через 5 минут.
6. Проверьте `/calendar`, `/inbox`, `/stats`, `/habits`, добавление и выполнение подзадачи, настройки сводки и тихих часов. Задача из входящих не должна отправлять уведомлений до назначения даты. Новые тихие часы выключены; включайте их только по желанию пользователя. Перезапустите сервер и убедитесь, что задачи и настройки сохранились. Локальные offline-тесты проверяют миграцию и доставку без Telegram; эта ручная проверка подтверждает работу именно хостинга.

Откат к старому коду после миграции требует остановки приложения и восстановления совместимой резервной копии по инструкции ниже. Изменения задач после момента этой копии при таком откате не сохранятся; сначала сохраните текущую базу отдельно. Не понижайте `user_version` вручную.

### Создание и восстановление копии

В Shell панели выполните из `/home/container`:

```sh
python -m bot.backup --output "backups/bot-$(date -u +%Y%m%dT%H%M%SZ).sqlite3"
```

Скачайте полученный файл через Files из `backups/` и храните отдельно. Команда работает при запущенном боте, включает зафиксированные изменения WAL и проверяет целостность; существующие копии не перезаписывает. Простое скачивание одного рабочего `data/bot.sqlite3` во время работы не заменяет backup.

Для восстановления остановите приложение и дождитесь завершения. Сохраните текущую базу отдельно, загрузите проверенную копию вместо `data/bot.sqlite3`; старые `-wal`/`-shm` этой базы убирайте только при отсутствии всех подключений. Затем запустите приложение и проверьте целостность и список задач. Рабочую SQLite не заменяют под запущенным процессом.

## Если запуск не удался

Проверьте логи Console: установка зависимостей при малой доле CPU может занимать несколько минут. При `ModuleNotFoundError` проверьте `requirements.txt`; при ошибке токена — секрет `BOT_TOKEN`; при `Conflict` — вторую копию бота. Для диагностики не публикуйте содержимое Env или SQLite.

Инструкции платформы: [настройка и загрузка файлов](https://bot-hosting.net/docs/guides/set-up-a-deployment), [Python hosting](https://bot-hosting.net/python-hosting), [SFTP](https://bot-hosting.net/docs/guides/connect-server-files-with-sftp).
