# Приоритет 2 — планирование

Реализованы только пункты 2.1–2.4 по уточнению владельца. Приоритеты 3 и 4 остаются в ROADMAP.md. Рабочая ветка — `feature/taskbot-planning-v2`, база — main после PR #1.

## Возможности

- **Утренняя сводка:** по умолчанию выключена, настройка времени и пустых дней, личный часовой пояс. Все категории, сокращение длинного списка, одна запись на местный день, lease и повторные попытки. Старая сводка не отправляется на следующий день. Снимок списка сохраняется при подготовке отправки. Настройки и подтверждение отправки сериализуются по пользователю.
- **Календарь:** месяцы, отметки дней, список со страницами, карточки и создание на выбранную дату. Повторяющиеся задачи проецируются в будущее без создания доставок. Отложенные основные экземпляры учитываются. При нескольких экземплярах одной задачи в один день показан ближайший; карточка управляет ближайшим экземпляром серии по прежним правилам. Выполненные и удалённые задачи не являются историей календаря.
- **Подзадачи:** до 100 пунктов на задачу, добавление, переименование, отметка, снятие отметки, удаление с подтверждением, страницы и общий прогресс. Родитель никогда не завершается автоматически. У серии список постоянный, отметки не сбрасываются при очередном повторе.
- **Входящие:** явный ввод через раздел, `/inbox` или `/inbox Название`. Срок — настоящий NULL, нет уведомлений и участия в календаре/сводке/обычных списках. Назначение даты сохраняет остальные данные и подзадачи. Обычный текст вне режима захвата не сохраняется автоматически.

Навигация объединена в «🗓 Планирование», без отдельной кнопки главного меню для каждой функции. Утренняя сводка находится в настройках, подзадачи — в карточке.

## Миграции

| Версия | Назначение |
|---|---|
| v5 | Поля сводки у пользователя и daily_summaries с уникальностью user/local_day |
| v6 | Таблица subtasks с FK на tasks, ревизией и мягким удалением |
| v7 | Nullable tasks.remind_at; недатированные повторы запрещены ограничением |

Миграции v1–v6 обновляются до v7 последовательно в одной транзакции; перед обновлением существующей SQLite создаётся проверенный backup рядом с ней. Для перестройки родительской таблицы задач в v7 SQLite требует временно отключить FK до BEGIN. Это происходит только на соединении запуска до передачи его приложению; все связи проверяются перед коммитом и FK включаются обратно. При ошибке схема и данные откатываются. ID задач, доставок, интервалов, подзадач и их связи сохраняются. Рабочая пользовательская база при разработке не открывалась.

## Проверки

**429 passed**: `python -m pytest -q -W error` на Python 3.12.9. Ruff, compileall, pip check и git diff --check прошли. Тестируются настройки и пустые дни сводки, личные пояса/DST, lease/перезапуск/конкурирующие соединения, отсутствие дублей, сериализация настройки с отправкой, календарные повторы, создание на дату, чужие и устаревшие действия, подзадачи/прогресс, входящие без доставки и последующее назначение срока.

Миграции проверены для схем v1–v6 с сохранёнными пользователями/настройками/задачами/состояниями доставок. Отдельно проверены дочерние строки при перестройке tasks, включение FK после миграции и откат при сбое после перестройки.

Для PR #1 исходные 391 тест прошли CI на Python 3.11–3.14 после исправления закрытия SQLite-соединений в тестах (`e8d98e4`). Приоритет 2 имеет собственный прогон CI перед слиянием. Docker Engine и реальный Telegram/хостинг не использовались. Неопределённый результат Telegram API имеет прежнее ограничение exactly-once: после потерянного ответа возможен дубль, несмотря на устойчивый журнал и lease.
