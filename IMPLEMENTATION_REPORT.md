# TaskBotTG improvements v1 — итог

Выполнены приоритеты 0 и 1 технического задания в ветке `feature/taskbot-improvements-v1`. Удалённый репозиторий и действующий хостинг не обновлялись. Пользовательская база не открывалась и не менялась.

## Реализовано

- Проверена существующая логика задач, повторов, доставок, переносов, часовых поясов, завершения процесса и прав доступа; исходные 321 тест прошли.
- Последовательные транзакционные миграции SQLite с `PRAGMA user_version`, backup перед обновлением существующей базы, откат DDL при ошибке или отмене, защита от более новой/неизвестной схемы.
- GitHub Actions для push/PR на Python 3.11–3.14: зависимости, синтаксис, критические ошибки Ruff, миграции и полный pytest без токена и сервера.
- Создание одним сообщением: относительные интервалы, даты, дни недели, время суток; уточнение неполных данных, подтверждение, исправление, отмена. Пошаговый диалог сохранён.
- Высокий/средний/низкий приоритет, изменение в карточке, отображение в списках и уведомлениях; сохраняемая личная сортировка по времени/важности.
- Пять стандартных категорий, необязательное изменение в карточке, сохраняемый личный фильтр и просмотр всех задач. Каталог допускает будущие категории с владельцем.
- Несколько предварительных предупреждений за 5/15/30/60/1440 минут: отдельные записи журнала, повторные попытки, lease, отмена устаревших отправок, поддержка серий, DST и перезапуска. Основная доставка не завершается предупреждением.
- README, инструкция безопасного обновления, журнал работы и план будущих версий.

## Миграции

| Версия | Изменение |
|---|---|
| 1 | Исходные users/tasks/deliveries |
| 2 | Приоритет задачи и личная сортировка; defaults medium/time |
| 3 | Каталог категорий, категория задачи и личный фильтр; defaults other/all |
| 4 | task_advances, граница начала предупреждений, kind/offset_minutes и расширенная уникальность доставок |

При запуске новая база создаётся сразу до v4, старая обновляется в одной транзакции. Перед обновлением создаётся проверенная копия в `backups/` рядом с исходной SQLite. Ошибка копирования останавливает запуск. Старые доставки становятся `main`, предварительные по умолчанию выключены. Для добавления вида и интервала таблица доставок перестраивается с сохранением исходных полей и ID.

## Ограничения

Быстрый разбор использует ограниченный набор правил, а не общий анализ естественного языка: неоднозначные или неполные данные требуют уточнения. Неподтверждённые черновики находятся в MemoryStorage и теряются после перезапуска. Создание собственных категорий в интерфейсе пока отсутствует.

Журнал предотвращает повторное создание одной доставки, но при неизвестном исходе Telegram API строгая гарантия exactly-once невозможна: если Telegram принял сообщение, а подтверждение потерялось, повторная попытка после lease может создать дубль. Эта граница существовала и у основной доставки. Точность зависит от интервала worker, нагрузки и доступности Telegram. История доставок и резервные копии занимают диск, автоматическая очистка пока не предусмотрена.

Предупреждения, прошедшие к моменту настройки или изменения срока, пропускаются. После простоя ранее запланированное предупреждение отправляется только до основного срока. Перенос отдельного уже наступившего экземпляра серии не создаёт ему новый набор предварительных предупреждений; регулярное расписание серии сохраняется. Однократный перенос поддерживает ещё будущие интервалы нового срока.

## Обновление действующего хостинга

Подробные команды и восстановление: [DEPLOYMENT.md](DEPLOYMENT.md#обновление-до-improvements-v1-со-старой-схемы).

1. Создать согласованный backup текущей серверной базы и скачать за пределы хостинга; проверить свободное место для автоматической копии и перестройки таблицы.
2. Остановить серверного бота и дождаться завершения.
3. Загрузить исходники проверенного коммита, сохранить Env с токеном и существующий `data/`. Локальную SQLite не загружать поверх серверной. Entry File — `main.py`, Python — 3.12.
4. Запустить приложение: обновление до v4 выполнится автоматически. Скачать дополнительный `data/backups/pre-migration-*.sqlite3`.
5. Проверить логи, существующие задачи/пояс/повторы, создать тестовую задачу и проверить новые функции, затем перезапуск с сохранением данных.

Для возврата старого кода требуется совместимая резервная копия; изменения после момента копии при откате теряются. Сначала сохранить и текущую базу. Никогда не понижать user_version вручную.
