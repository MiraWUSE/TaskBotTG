# Развитие TaskBotTG v1

Рабочая ветка: `feature/taskbot-improvements-v1`. Изменения выполняются локально; публикация и обновление хостинга требуют отдельного разрешения владельца.

## 0.1. Проверка исходной реализации

Изучены запуск и завершение приложения, обработчики и middleware, клавиатуры, сервис задач, worker, схема SQLite, утилиты дат, backup, тесты, README и инструкция развёртывания.

Подтверждены проверки владельца и приватного чата; изоляция FSM; версии кнопок; отмена доставок при изменении расписания; отдельная обработка экземпляров повторяющейся серии; UTC и IANA-пояса; DST; атомарные резервирования отправок, восстановление lease, повторные попытки и резервное копирование WAL. Тесты выполняются без сети и реального Telegram-токена.

Исходная проверка: `python -m pytest -q -W error` — **321 passed**. Блокирующих ошибок в существующем поведении не выявлено. Для расширения требуется заменить повторное исполнение общей схемы механизмом последовательных транзакционных миграций; CI отсутствует. Это следующие пункты плана.

Рабочая пользовательская SQLite, токен и серверное приложение при разработке не изменяются. Все проверки схемы выполняются во временных тестовых базах.

## 0.2. Миграции SQLite

Схема v1 вынесена в `bot/database/migrations.py`, подключение использует последовательные транзакционные миграции. Номер версии и DDL фиксируются вместе; повторный запуск пропускает уже применённые изменения. Перед обновлением существующей базы создаётся проверенная backup-копия, ошибка копирования отменяет запуск. Неизвестная и более новая схемы отклоняются. Рабочая база не открывалась.

Изменены `bot/database/db.py`, `README.md`; добавлены `migrations.py` и `tests/test_migrations.py`. Проверены старая схема с пользователем, задачей и доставкой, последовательность обновлений, повторный запуск, откат DDL при сбое и отказ при ошибке backup: **5 passed**. Сама схема пока остаётся v1; новые поля будут отдельными миграциями в соответствующих пунктах.
